YAML · Tab indents · Ctrl+Space completes

Format

name: Human readable title
category: Gap locks          # optional; folder name is used otherwise
description: |
  Markdown. **Bold**, `code`, lists and headings all render
  on the scenario page.
tags: [gap-lock, insert-intention]

mysql:
  image: mysql:8.4
  isolation: REPEATABLE READ  # or READ COMMITTED, SERIALIZABLE
  lock_wait_timeout: 300      # seconds, per session
  deadlock_detect: true       # global; false turns deadlocks into timeouts
  prepared: false             # true sends COM_STMT_EXECUTE, binary result rows
  vars:                       # extra SET SESSION variables
    sql_mode: STRICT_ALL_TABLES

schema:
  - CREATE TABLE t (...)

seed:
  - INSERT INTO t VALUES (...)

actors:
  - id: a
    name: Request A
    accent: blue              # blue amber violet teal rose
  - id: b
    name: Request B

steps:
  - actor: a
    label: Open a transaction
    sql: BEGIN
    note: Shown next to the step in the timeline.
    expect: ok                # ok blocks error deadlock timeout

How stepping works

Each step is submitted on its actor's own connection and given {{.Settle}} ms to finish. If it has not returned by then it is marked blocked and left running, so you can advance the other actor and watch the two interact. A blocked step updates itself when it finally succeeds, times out, or is picked as a deadlock victim.

Useful things to assert

  • expect: blocks — the statement should hit a lock wait. It still counts as met if the statement later completes, times out or is rolled back.
  • expect: deadlock — this actor should be the victim (errno 1213).
  • expect: timeout — innodb_lock_wait_timeout should fire (errno 1205).

Ordering rule

A connection runs one statement at a time, so a blocked actor cannot accept its next step. Put the statement that releases the lock — usually a COMMIT on the other actor — before the blocked actor's next step.
