Format reference

 
name: Human readable title
category: Gap locks          # optional; folder name is used otherwise
description: |
  Markdown. **Bold**, `code`, lists and headings all render
  on the scenario page.
tags: [gap-lock, insert-intention]

mysql:
  image: mysql:8.4
  isolation: REPEATABLE READ  # or READ COMMITTED, SERIALIZABLE
  lock_wait_timeout: 300      # seconds, per session
  deadlock_detect: true       # global; false turns deadlocks into timeouts
  prepared: false             # true sends COM_STMT_EXECUTE, binary result rows

schema:
  - CREATE TABLE t (...)

seed:
  - INSERT INTO t VALUES (...)

actors:
  - id: a
    name: Request A
    accent: blue              # blue amber violet teal rose
  - id: b
    name: Request B

steps:
  - actor: a
    label: Open a transaction
    sql: BEGIN
    note: Shown next to the step in the timeline.
    expect: ok                # ok blocks error deadlock timeout

The ordering rule

A connection runs one statement at a time, so a blocked actor cannot accept its next step. Put the statement that releases the lock — usually a COMMIT on the other actor — before the blocked actor's next step. The step pane flags this for you.

Stepping

Each step gets {{.Settle}} ms to finish before it is reported as blocked, and keeps running in the background after that.
